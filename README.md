# ESP32-P4 + ES9039Q2M аудиоплеер

Стационарный аудиоплеер (DAC-плеер + сабвуфер) на плате Waveshare ESP32-P4-WIFI6-Touch-LCD-5 с цветным 5" IPS-экраном. Среда разработки: VS Code + ESP-IDF 6.1.

---

## Аппаратная база (проверено по схеме платы)

| Узел | Реализация |
|---|---|
| ЦАП | ES9039Q2M (плата Arvin DAC + OPA1612), I²C 0x48, режим SW — P4 подаёт только BCLK/LRCK/DATA (ASYNC slave) |
| Канал сабвуфера (ЭМОС) | PCM5102A (запасной PCM5142A) |
| АЦП-тракт | WM8782 + FDA OPA1632 |
| Дисплей | IPS 720x1280, HX8394, MIPI-DSI 2 lane (58 МГц, 30 Гц), питание PHY — LDO канала 3 (2.5 В) |
| Подсветка | контроллер AP3032KTR-G1: BL_PWM = **GPIO26** (LEDC 20 кГц), BL_EN = **GPIO33**; I²C в подсветке нет |
| Тач | GT911 по I²C 0x5D/0x14; RST = **GPIO23**, INT = GPIO2 (R108 «NC/OR» — пока поллинг, INT выключен) |
| I²C шина | GPIO7 (SDA) / GPIO8 (SCL), 100 кГц (ЦАП + тач) |
| SD-карта | SDMMC2 4-bit: CLK GPIO43, CMD GPIO44, D0..D3 GPIO39..42; питание — внутренний LDO канала 4; DETECT отсутствует |
| USB | порт Type-C «USB» → OTG High-Speed P4 (USBD_P/N); второй Type-C — UART-мост для прошивки/логов |
| I²S | **BCK = GPIO46 (#35), WS/LRCK = GPIO47 (#37), DATA/SD0 = GPIO48 (#39)** — подтверждено схемой 19.11.2026; automute-пин ЦАПа = GPIO4 |
| Wi-Fi/BLE | сопроцессор ESP32-C6 на плате (ESP-Hosted / esp_wifi_remote), 2.4 ГГц |
| Память | 32 МБ Flash, PSRAM 250 МГц (REV3 чип) |

## Возможности (по убыванию значимости)

### 1. Полный аудио-конвейер
- Декодер `esp_audio_simple_dec` (espressif/esp_audio_codec): MP3 / FLAC / WAV, автодетект по расширению и заголовку.
- **DSD через DoP** (dsd_dec.c): файлы DSF/DSDIFF (.dsf/.dff) — потоковый парсер + упаковка в DoP 24-бит с маркером 0x05/0xFA в старших битах (чередование каждые 256 фреймов); DAC переводится на вход DoP (Reg 1 = 0x84) и обратно на PCM по завершении. Частоты шины: 176.4 кГц (DSD64), 352.8 кГц (DSD128), 705.6 кГц (DSD256), 192 кГц (DSD64-48k).
- Конверсия любого входа в 32-бит стерео (16→<<16, 24→sign-extended <<8, mono дублируется).
- I²S стандартный режим, 32-бит слоты stereo, auto_clear.
- Управление частотой на лету: смена 44.1/48/96 кГц с пересборкой FIR и ожиданием SRC lock.

### 2. Избранные радио-станции (вкладка «Радио»)
- Список в NVS (namespace "dac", blob-ключ "stations", до 10 станций по 64+256 символов); переживает питание.
- Добавление: текущий источник (http(s)://) + имя (пусто — hostname из URL); дедупликация по URL.
- Выбор: тап по станции — играет (set_source_url, очередь плейлиста сбрасывается); долгий тап — удаление.

### 3. Скан Wi-Fi из UI (вкладка «Сеть»)
- Асинхронный скан (esp_wifi_scan_start, блокирующая задача + опрос из LVGL-таймера, UI не замерзает).
- Список найденных сетей (до 20, отсортированы по уровню сигнала): открытые/скрытые помечены иконкой, RSSI в строке.
- Тап по сети подставляет SSID в поле; дальше пароль и «Подключить».

### 4. Автотушение подсветки (вкладка «Настройки»)
- Таймаут неактивности: «Никогда / 1 / 5 / 15 минут» — хранится в NVS (ключ "bl_timeout").
- Неактивность — от LVGL (`lv_display_get_inactive_time`): любое касание сбрасывает счётчик; гашение — duty LEDC → 0 (BL_PWM GPIO26).
- Тап по погашенному экрану будит и обрабатывается (двухфазное пробуждение не делали); если тач не поднялся — автотушение отключено, чтобы экран не гас без пробуждения.

### 5. ЦАП ES9039Q2M (драйвер, ~36 КБ исходников)
- Полная инициализация: питание, часы, reset, входной формат, деэмфазис, фильтры.
- Регулировка громкости: 0..-127.5 дБ шагом 0.5 (Reg 74/75), mute, soft ramping.
- Штатные пресеты фильтров (Reg 88, 0..7) с описанием звучания каждого.
- Автомут на GPIO4 при отсутствии потока.
- Диагностика: `es9039_diag_read()` — снимок состояния (SRC lock, оценка частоты по данным чипа, поедание BCK/WS, автоматут, soft ramping, chip_id).
- DPLL bandwidth (Reg 29), очистка прерываний (Reg 20/21), THD-компенсация (Reg 91–94/107–110, 16-бит signed, output = x + c2·x² + c3·x³) — по мотивам авторских настроек vladikb.

### 6. Кастомные FIR-фильтры (уникальная фича)
- 16 готовых наборов: C-BRICK и C-SLOW под **все 8 частот** 44.1/48/88.2/96/176.4/192/352.8/384 кГц (генерируются tools/gen_fir_coeffs.py, самодостаточный).
- Модель каскада 2x(128 тапов) + 4x(32 тапа) подтверждена численно; групповая задержка совпадает со штатным «linear phase fast roll-off» ESS.
- Спецификации: BRICK — стоп от 0.55·fs (96k — от 24 кГц), чистовая от 1.5·fs; SLOW — переход 20 кГц–0.72·fs, чистовая от 1.44·fs. Рябь 0.000–0.08 дБ, образ fs до −133 дБ (на высоких fs RAM даёт больше подавления, чем на 44.1k).
- Квантование Q1.23: если пик после нормировки суммы = R·(2^23−1) выходит за 1.0 (свойство узкополосного ФНЧ — так было у C-SLOW 44k с багом: загрузка падала), набор перенормируется по пику — форма сохраняется, общий гейн ниже на ~0.1 дБ (только C-SLOW 44k).
- Загрузка через Reg 135/137/138–140 (24-бит знаковый), readback Reg 246–248.
- Выбор набора из UI (0 = авто, 1..N = ручной), автозаливка при смене частоты потока; для частот без набора (напр. DoP256 = 705.6 кГц) — возврат к встроенному пресету.
- Генератор новых наборов: `tools/gen_fir_coeffs.py` (Parks-McClellan с фолбэком на окно Кайзера; проверка симуляцией целочисленного каскада).

### 7. Воспроизведение: 3 типа источников
- **SD-карта** — источник по умолчанию: при старте ищется первый `.mp3/.flac/.wav/.dsf/.dff` (в глубину до 3 уровней папок) и играется.
- **HTTP-файл** — музыка с NAS/ПК (любой HTTP-сервер), URL сохраняется в NVS.
- **HTTP-поток** — интернет-радио (без Content-Length, неограниченные retry).
- **Метаданные на «Главной»** (meta.c): название (крупно) и исполнитель — из ID3v2.2/2.3/2.4 (MP3; кодировки ISO-8859-1, UTF-16 с BOM и без, UTF-8), vorbis comments (FLAC), ID3v1-фолбэк (последние 128 байт файла), ID3 из DSF (metadata pointer в конце файла); для радио — StreamTitle через Icy-MetaData (запрос с Icy-MetaData:1, парс icy-metaint из ответа, обновление в реальном времени); для радио «Artist - Title» в одном поле разбирается на два.
- **Обложка альбома** слева на «Главной»: ID3v2 APIC/PIC и FLAC PICTURE (тип 3 front cover, иначе первый встречный) — до 1.5 МБ в PSRAM; JPEG декодируется АППАРАТНЫМ декодером P4 (esp_driver_jpeg) в RGB565 с паддингом строки до 16 px через stride дескриптора; PNG пока не декодируется (софт-декодер — отдельный компонент). Декодирование — по смене трека (serial), в LVGL-таске (~50-150 мс).
- Вкладка «Файлы»: браузер папок/файлов SD прямо на экране; выбор трека тапом; файлы `.m3u/.m3u8` — очередь из плейлиста (абсолютные пути, относительные к папке плейлиста и http-ссылки).
- **Управление воспроизведением на «Главной»**: prev / play-pause / next (иконка меняется), прогресс-слайдер с точным временем (мм:сс / мм:сс; скрыт для радио); для радио пауза работает как mute (декодер продолжает — буфер не переполняется), для файлов — настоящая пауза.
- **Перемотка (скраб)**: тап/драг по слайдеру — показ времени в точке курсора, отпускание — `decoder_seek()`: рестарт конвейера с байтового офсета (file:// — fseek, http:// — Range, ответ 206 с Content-Range разбирается). Поддержано: MP3 (CBR ~1-2 кадра, VBR — эмпирика bytes/сек по факту воспроизведения), DSD — точный seek по кадрам (DSF — кратен супергруппе, DFF — интерливированные байты; DoP-маркер сбрасывается). FLAC/WAV — пока не перематываются (мид-стрим-рестарт требует заголовок; TODO: seektable FLAC, проверка sync на железе). Пауза сохраняется через seek.
- **Точный прогресс**: позиция — по декодированным сэмплам (`samples/fs`), не по позиции чтения файла; длительность — `file_size*8000/bitrate` из первого кадра декодера, при отсутствии битрейта — эмпирика consumed/played (VBR).
- **Плейлист и авто-переход** (playlist.c): очередь из .m3u или из папки (неявно, отсортированная по имени); по концу трека — авто-переход к следующему, next/prev — соседние треки; prev в начале очереди перезапускает текущий трек.
- Вкладка «Сеть»: смена URL на лету (декодер перезапускается, URL сохраняется).
- Буферизация: ringbuf 256 КБ в PSRAM.
- **Асинхронный декодер (P2)**: ringbuf и источник (http/phono/ADC) поднимаются в задаче декодера, а не в вызывающем контексте; переключение источников — через `decoder_request()` (текущее останавливается, новое встаёт в очередь и стартует сразу после выхода задачи) — переключение радио больше не блокирует httpd/UI на 1–2 с. `decoder_start/request/stop/pause/resume` — под общим мьютексом декодера; хуки громкости/mute/фильтра/FIR в main.c — под общим мьютексом хуков (гонки плейлиста отложены — playlist.c вне патча).

### 8. SD-карта как USB-диск для ПК (на лету)
- MSC-класс через espressif/esp_tinyusb ^3.0 (OTG High-Speed P4): ПК видит карту как сменный диск.
- Чтение и запись на лету: подключили кабель — карта переходит к ПК, отсоединили/Eject — возвращается плееру, воспроизведение file:// возобновляется автоматически.
- HTTP-источники не прерываются; UI показывает «Карта у ПК (USB)».
- Скорость: ~4.7 МБ/с чтение / ~2.1 МБ/с запись (P4, FIFO 8192).
- Владение картой переключает сам компонент MSC (auto_mount), приложение только останавливает/возобновляет чтение.

### 9. Графическая оболочка (LVGL 9)
- 7 вкладок: **Главная** (громкость, mute, источник, обложка, название трека), **Радио** (избранные станции), **Фильтры** (пресет Reg 88 + FIR-набор), **Диагностика** (состояние ЦАПа раз в секунду), **Настройки** (язык, подсветка, автотушение, спящий режим), **Сеть** (Wi-Fi SSID/пароль, скан сетей, URL источника), **Файлы** (браузер SD).
- Два языка: EN/RU, полная перестройка интерфейса без перезагрузки.
- Собственные шрифты NotoSans 16/28/40 с кириллицей (~0.9 МБ Flash); скрипт регенерации `tools/generate_fonts.sh`.
- Экранная клавиатура LVGL: латиница (SSID/URL) + **кириллица ЙЦУКЕН** (режим «спец»-кнопки переключает EN/RU/цифры).
- Громкость: слайдер 0..255 → 0..-127.5 дБ, шаг 0.5 дБ; подсветка: слайдер 0..100% с сохранением в NVS (стартовый уровень — сохранённый, иначе 80%).
- Смена языка/подсветки/темы — сохраняются при выходе из экрана (в NVS).
- **Автотушение подсветки**: тайм-аут неактивности (LVGL), гашение duty→0, тап будит; «Никогда/1/5/15 мин», NVS.
- **Спящий режим**: после гашения подсветки панель уходит в Sleep In (0x28 через DBI), Wi-Fi выключается (если не играет радио); пробуждение касанием — Sleep Out + Wi-Fi включается только по явному действию (выбор радио или скан). «Никогда/5/15/30 мин», NVS.

### 10. Wi-Fi через сопроцессор ESP32-C6
- STA-режим, подключение по SSID/паролю, введённым с экрана (NVS: wifi_ssid/wifi_pass).
- Пустой пароль = открытая сеть (WIFI_AUTH_OPEN).
- Поддержка esp_wifi_remote (ESP-Hosted) — Wi-Fi живёт на C6, главный P4 только API.
- Переподключение на лету: применение новых кредов сразу (disconnect + connect).
- Сетевой буфер 256 КБ, защита от обрывов (10 попыток, экспоненциальный backoff).

### 11. Веб-пульт (web_ctrl.c)
- Мини-HTTP-сервер (esp_http_server, порт 80) стартует в main.c после Wi-Fi; доступ — через те же ui_hooks_t, что и UI: громкость/mute/next/prev/источник выполняются ровно тем же кодом (NVS-сохранение громкости работает).
- HTML/CSS/JS пульта вынесены в `main/web_root.h` (автогенерируется: правки — в `tools/web_page.html`, затем `python tools/gen_web_root.py` из корня проекта); в `web_ctrl.c` — только сервер и REST API.
- Эндпойнты: GET / (HTML-пульт), GET /api/status, POST /api/volume?v=0..100, POST /api/mute[?on=], POST /api/play, POST /api/next|prev, POST /api/seek?ms= (MP3/DSD, включая DST-DFF), POST /api/src?u=, GET /api/files?path=[&root=usb|sd][&off=0&lim=200] (пагинация: ответ содержит count/off/items, веб-подгружает по 100 записей, «… ещё N» внизу), POST /api/playfile?p=[&root=usb], GET /api/stations, POST /api/station?i=, GET /api/diag, POST /api/phono, POST /api/hpf?v=0|1|2, POST /api/dsd?v=0|1 (DoP/Native), POST /api/ota?file=|u=.
- HTML-пульт: статус (state/IP/SSID/vol/fs/dsd/hpf), прогресс с кликом-перемоткой (если seekable), слайдер громкости, play/prev/next, URL источника, навигация по SD/USB и станции, блок DSD mode (DoP/Native), кнопка PHONO и блок Phono subsonic HPF. Обновление статуса раз в 2 с. CORS включён.
- Безопасность: без аутентификации (домашняя сеть; не выставлять в интернет).
- Ограничения: смена источника не блокирует httpd (асинхронный decoder_request, P2); громкость с телефона не отражается на слайдере экрана до пересборки UI (TODO: лёгкая синхронизация в prog_tick).
- Подсказка DSD mode: под кнопками DoP/Native пояснение про проводку DATA2/DATA_CLK и применение со следующего DSD-трека.

### 12. OTA-обновление прошивки (ota_upd.c)
- Требуется таблица разделов `partitions.csv` (ota_0 + ota_1, идёт в патче): дефолтная single-app таблица OTA не поддерживает. Первая прошивка этой таблицы — **только по кабелю**: `idf.py fullclean`, затем `reconfigure` (в sdkconfig.defaults добавлена `CONFIG_PARTITION_TABLE_CUSTOM`), затем `flash`. После этого обновления — без кабеля.
- Эндпойнт: `POST /api/ota?file=firmware.bin` (файл на SD, кнопка SD на пульте) или `POST /api/ota?u=http://server/firmware.bin` (URL; https — с системными корневыми сертификатами, как у декодера).
- Проверки до записи: файл существует, первый байт 0xE9 (ESP-IDF образ), размер > 32; для URL — статус 2xx. После записи esp_ota_end() ещё раз валидирует образ; только затем esp_ota_set_boot_partition().
- Прогресс: в `/api/status` поля `ver` (версия текущей прошивки) и `ota.state/pct/msg`; индикатор в HTML-пульте. По успеху — автоматический ребут через ~2 с (HTTP-ответ успевает уйти).
- Rollback (патч dsd_p1p2_fix_patch): после успешного старта прошивка вызывает `ota_upd_confirm_app()` — при `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y` образ помечается валидным; если обновлённая прошивка не стартовала и не подтверждена, загрузчик сам откатывается на предыдущую партицию. Проверьте в sdkconfig, что опция включена — без неё вызов не даёт эффекта отката.
- Имя файла по умолчанию — `firmware.bin` в корне SD. Во время записи Wi-Fi должен оставаться включённым; питание не выключать.

### 13. Флешка как источник: USB-хост на OTG FS (usb_flash.c)
- Второй порт USB платы (Full-Speed, GPIO24/25) — хост: флешка монтируется FatFS в `/usb` (BOT/SCSI поверх espressif/usb_host_msc ^1.3.0; стек espressif/usb подтянется транзитивно).
- TinyUSB MSC (SD как диск для ПК) живёт на OTG HS — стеки независимы; проверено по HAL esp32-p4: USB_DWC_LL_GET_HW(1) == USB_DWC_FS.
- Играть с флешки: веб-пульт — переключатель SD/USB над списком файлов (root=usb), либо `/api/playfile?p=<путь>&root=usb`. next/prev работают по папке флешки автоматически (очередь строится лениво из папки текущего файла).
- Извлечение флешки во время воспроизведения — декодер останавливается автоматически (хук on_unmounted в main.c).
- Формат FAT32/FAT16; NTFS не смонтируется (FatFS). Прожорливые диски/хабы — через хаб с внешним питанием.
- Индикация: лог usb_flash («Флешка: <имя> ...», «Готово: /usb»).

## 14. АЦП-тракт WM8782: винил/линия (phono_adc.c, pipeline_192k.h)
- Новый источник `adc://`: I²S RX 192 кГц (24 бит в 32-битных слотах) -> DSP-канал (trim -> DC-блокер 5 Гц -> RIAA FULL (IEC 60098 с полюсом Нойманна 3,18 мкс) -> сабсонический HPF OFF/GENTLE/STRICT с 10 мс кроссфейдом) -> peak monitor -> ringbuf -> decoder (passthrough) -> i2s_out -> ES9039Q2M. Пауза, громкость, фильтр DAC — работают как обычно; seek/длительность недоступны (живой поток).
- **Тактирование: по умолчанию P4 = мастер** (как на схеме Input_Buffer WM8782S): P4 подаёт MCLK 256·fs = 49,152 МГц (GPIO14, внутренний аудио-PLL — фазовый шум проверить на бенче), BCLK GPIO15, LRCK GPIO16; вход DATA GPIO17. На модуле WM8782 включить SLAVE-перемычку (иначе конфликт клоков). Альтернатива PHONO_CLK_SLAVE (модуль-мастер с кварцем 24,576) — флаг в phono_adc.c, сравнить idle-шум по методике README пакета (п.4), оставить лучший.
- Пины (ПО ПЛАТЕ ПРОВЕРИТЬ): MCLK=14, BCLK=15, LRCK=16, DATA=17. С основным трактом DAC (46/47/48) не пересекаются.

### 14.1 Как это работает
- Новый источник `adc://`: I²S RX 192 кГц (24 бит в 32-битных слотах) → DSP-канал (trim → DC-блокер 5 Гц → RIAA FULL (IEC 60098 с полюсом Нойманна 3,18 мкс) → сабсонический HPF OFF/GENTLE/STRICT с 10 мс кроссфейдом) → peak monitor → ringbuf → decoder (passthrough adc://) → i2s_out → ES9039Q2M.
- Пауза, громкость (−127,5…0 дБ), фильтр DAC, FIR — работают как обычно. Seek/длительность недоступны (живой поток): позиция идёт по сэмплам, `total_ms = 0`, `seekable = false`, seek → `ESP_ERR_NOT_SUPPORTED`. Авто-переход по плейлисту для adc:// не вызывается.
- Блок приёма: задача `phono_rx` (prio 10, 8 КБ) читает DMA блоками 10 мс (1920 стерео-фреймов), конверсия int32→float32→DSP→int32, запись в ringbuf (256 КБ PSRAM). Суммарная задержка тракта ~25–40 мс. CPU ≈ 1–2 % ядра.
- Пик-монитор: warn −1 дБFS (0,8913), clip −0,5 дБFS (0,9440); лог раз в 6 с при клипах; счётчики через `phono_adc_stats()`.

### 14.2 Тактирование: P4 = мастер (по умолчанию)
- P4 подаёт MCLK **256·fs = 49,152 МГц** (GPIO14, внутренний аудио-PLL), BCLK 12,288 МГц (GPIO15), LRCK 192 кГц (GPIO16); DATA GPIO17 — вход от модуля. Формат — I²S Philips.
- На модуле WM8782 включить **SLAVE-перемычку** (два мастера на шине конфликтуют), FORMAT-джампер открыт (I²S), 1/2CLK — вне положения 1/2CLK.
- Проверить на бенче: (а) фазовый шум аудио-PLL на 49,152 МГц (idle-запись 30 с с шунтом 10 Ом, FFT — спуры PLL кратные клоку); (б) альтернатива `PHONO_CLK_SLAVE` (модуль-мастер с кварцем 24,576 МГц) — сравнить пол по методике README пакета, оставить лучший; (в) порядок каналов (`left_right_order`) — при перепутанных L/R сменить константу.
- Частота фиксирована 192 кГц в обоих вариантах: константы RIAA/HPF рассчитаны только для неё (на 96 кГц кривые «уедут»).

### 14.3 Пины и коммутация

|---|---|---|
| MCLK | GPIO14 | → модуль (только P4-мастер) |
| BCLK | GPIO15 | ↔ модуль BICK |

### 14.4 Схема тракта (по листу входного буфера)
- MM/LINE — реле TAKAMISAWA RY15W-K + ULN2003; выход преда OPA1656 → делитель 15к/5к (SE-съём 0,25×) → OPA1632 (FDA) + AD8221, REF3025 2,5 В → anti-aliasing ~440 кГц → AINL/AINR.
- Псевдодифференциальное подключение: sense — аналоговая земля → 10 мкФ → COM (пин 17); штатная подтяжка COM к VMID ~3,3 кОм — проверить прозвонкой.
- Буферы клока: SN74LVC1G17DBVR, SN74LV125AN; в линиях клока 33/47/100/470 Ом.
- Питание: LP2985-5 → AMS1117-3.3; PSRR чипа всего 50 дБ — феррит + 100 мкФ тантал + 100 нФ у VCC.
- Земля: силовая/аналоговая/цифровая зоны, соединение в одной точке; GND модуля (экраны RCA) → аналоговая земля.

### 14.5 Приёмка модуля (до первого включения)
1. DVDD (пин 5) = 2,7–3,6 В; если 5 В — перерезать дорожку VCC→DVDD, врезать LDO 3,3 В (ME6211C33/HT7333).
2. FORMAT-джампер открыт (I²S); GND звонится на экраны RCA; DGND отдельный.
3. Гнездо 3,5 мм не шунтирует RCA пустым джеком (частая ловушка Ozon-версии).
4. Стрэпы: 24bit; SLAVE — ВКЛЮЧЁН; FSAMPEN=NC (192 кГц); 1/2CLK вне положения 1/2CLK.
5. Питание: феррит + 100 мкФ тантал + 100 нФ у VCC; опция — малошумящий LDO 5 В.
6. Земли — одна точка на плате входов (см. 14.4).
7. Псевдодиф: сигнал → AINL/AINR; sense: аналоговая земля → 10 мкФ → COM.

### 14.6 Бенч-методика
- **Idle-шум**: вход шунт 10 Ом, преды обесточены; запись 30–60 с @192к/24; широкополосный RMS + A-взвешенный пол + FFT (50/100 Гц, спуры тактирования). Ожидание модуль-мастера ~−98 дБFS(A); P4-мастер сравнить — при хуже на 3+ дБ вернуться к модулю-мастеру. Прогрев 10–15 мин.
- **Калибровка FS и trim**: генератор 1 кГц, нарастать до порога клипа пик-монитора; FS = найденный уровень; trim = 1.0/FS(отн. рабочей точки). Рабочая точка: линейный вход 2 Vrms → −6 дБFS (съём 0,25× при FS чипа ~1 Vrms — сверить измерением).
- **Самотест DSP**: `phono_run_all_tests()` после старта (~3 с): RIAA 20/100/1к/5к/10к/20к (±0,3 дБ), GENTLE (±0,5), STRICT (0,7–1,2), DC, NaN, кроссфейд (0,10 FS).

## 15. Native DSD (без DoP-обёртки) и DST-сжатые DFF (dsd_native.c, dst_dec.c)

### 15.1 Native DSD — что нужно
- Native DSD (DSD64–DSD512) на ES9039Q2M идёт не через BCK/WS, а по трём линиям: **DATA1 = DSD CH1 (L)**, **DATA2 = DSD CH2 (R)**, **DATA_CLK = бит-клок DSD** (Reg 64/65: DSD_CH1_SOURCE=DATA1, DSD_CH2_SOURCE=DATA2; Note к Reg 57: при AUTO_INPUT_SEL DSD-линии обязаны быть на DATA1/DATA2). BCK/WS чипом в этом режиме не читаются.
- На плате Arvin DAC разведён только DATA1 (штатный «DATA» GPIO48). **DATA2 (пин 14 чипа) и DATA_CLK (пин 12 чипа) требуют пайки** от P4 (по умолчанию в патче: DATA2→GPIO49, DATA_CLK→GPIO50 — константы в dsd_native.h, сверить по схеме платы). Без этих проводов native DSD физически не подаётся — веб-кнопка «Native» откатится на DoP с логом.
- P4: два I²S-порта — A (TX master, слоты 8 бит, BCLK = 64·fs, dout → DATA1) и B (TX slave, BCLK/WS — входы от порт A, dout → DATA2). Пишутся из одной задачи: порт A — [L,0]-интерлив, порт B — [R,0]-интерлив. Регистры: `es9039_set_input(ES9039_INPUT_DSD)` (Reg1=0x82, Reg57=0x41 AUTO) при старте, обратно PCM при завершении; MCLK остаётся от локального генератора (DSD-ASYNC: MCLK 6·fs…50 МГц, DSD64–DSD512).
- Управление: кнопки **DoP / Native** в веб-пульте (блок DSD mode), `POST /api/dsd?v=0|1`, поле `dsd` в `/api/status`; сохраняется в NVS (`dac/dsd_mode`), применяется при старте. На время native штатный PCM-порт ставится в паузу (`i2s_out_set_paused(true)`) — иначе два DMA дерутся за GPIO48/GPIO47; позиция трека в UI идёт по сэмплам.
- Риск: TX-slave на P4 и фазировка двух портов — проверить на бенче; при сбоях — DoP.
- Пауза/восстановление: dsd_native_pause(true) останавливает клок (ES9039 по fault-detect уходит в тишину, позиция файла не двигается); при снятии — клок возвращается и Reg1/57 переписываются. decoder_pause/resume различают native через dsd_native_running().

### 15.2 DST-сжатие DFF (dst_dec.c)
- DST — сжатие DSD (ISO/IEC 14496-3 subpart 10, стандарт SACD). Структура DSDIFF (spec v1.5): чанк **«DST »** содержит под-чанки: **FRTE** (обязательно первым: numFrames u32 BE + frameRate u16 BE = 75), последовательные **DSTF** (сжатые фреймы, каждый декодируется независимо) и опциональные **DSTC** (CRC 4 байта после каждого DSTF; pad-байт после нечётного ckDataSize пропускается).
- Размер декодированного фрейма: `DSD_rate/75` бит на канал (DSD64: 4704 бит = 588 байт/канал); вывод — интерлив L,R MSB-first (как DFF «DSD ») — совместим с пайплайном DoP/native напрямую.
- Декодер — перенос libavcodec/dstdec.c (FFmpeg, **LGPL-2.1+**, (c) 2014 Peter Ross): bit reader, арифметический декодер, таблицы filter/probability sets. Поддержаны same segmentation/mapping, 1–2 канала, DSD64/128/256 (кратно 44100). Сбойные фреймы пропускаются с повтором предыдущего.
- Golomb-формула сверена с ffmpeg libavcodec/golomb.h (не-cached ветка): value = (i << k) + bits, где i — число нулей; прежняя формула с −(1<<k)+1 была неверна — заменена.
- DSF с format id = 1 (DST в DSF) — **не поддерживается** (в логе подсказка использовать DFF). Seek в DST — последовательный пропуск DSTF/DSTC-заголовков (75 фрейм/с — быстро).
- Не проверен на реальном SACD-DFF (нет примера в среде подготовки) — проверьте на своём файле; при сбоях декодера смотрите лог повторов фреймов.
- Счётчик повреждённых DST-фреймов (`s_dst_err_frames`): в логе первая ошибка и далее каждая 16-я — для диагностики качества файла.

### Известные ограничения (не баги, а осознанные решения)
- Пароль Wi-Fi хранится в NVS открытым текстом — приемлемо для домашнего плеера, ключ `wifi_pass` в NVS можно стереть.
- SD-карта не подхватывается «горячей» вставкой (DETECT-пина нет) — вставка до включения.
- FIR-фильтры не переживают сброс (RAM ESS) — прошивка восстанавливает их при каждом старте и смене частоты.
- DSD: поле «bits per sample» в DSF (1 или 8) задаёт и битовый порядок (1=LSB first, 8=MSB first — сверено с ffmpeg dsfdec.c); bits=8 — редкий формат, трактуется как обычный DSD-байтовый поток.
- DoP: маркер чередуется 0x05/0xFA каждые 256 стерео-фреймов; DoP-фрейм = 2 слота [marker|DSD_L|0] / [marker|DSD_R|0].
- FIR-наборы при DoP не задействованы: DSD-тракт чипа минует PCM-интерполятор; залитый набор остаётся в RAM и снова работает при возврате в PCM.
- Сабвуфер PCM5102A при DoP получит DoP-поток как PCM с маркерами (ультразвуковой мусор) — сабвуферный канал в прошивке пока не реализован, реализовать с фильтрацией или отключать при DSD.
- Прочие файлы на SD (не .mp3/.flac/.wav/.dsf/.dff) в браузере не показываются.

## Журнал патчей

### 3.6.3 (P2/P3): асинхронный декодер, мьютексы, пагинация

- **decoder_start асинхронен**: ringbuf и источник (http/phono/ADC) поднимаются в задаче декодера, а не в вызывающем контексте. Переключение радио больше не блокирует httpd/UI на 1–2 с коннекта.
- **decoder_request()** — асинхронное переключение источника: если играет — текущее останавливается, новый источник ставится в очередь (`next_url/next_type/next_stream/next_queued` в ctx) и стартует задачей декодера сразу после её выхода. Везде, где было `decoder_stop()+decoder_start()` (set_source_url, next/prev, авто-переход), теперь decoder_request.
- **Мьютекс декодера** (decoder.c): decoder_start/request/stop/pause/resume под общим мьютексом — двойной старт и потерянный переход исключены. Ожидание выхода задачи под мьютексом не держится (без дедлоков).
- **Мьютекс хуков** (main.c): громкость/mute/фильтр/FIR/Wi-Fi под общим мьютексом — вызовы из LVGL-задачи и httpd не гонятся. Гонки плейлиста закрыть нечем (playlist.c в патче нет) — отложено.
- **NVS namespace**: проверено — web_ctrl пишет namespace "dac" ключ "dsd_mode", persist в main.c читает тот же namespace/ключ. Расхождений нет (комментарий добавлен в api_dsd).
- **/api/files пагинация**: параметры `off` (смещение, дефолт 0) и `lim` (дефолт WEB_FILES_MAX=200, максимум 200). Ответ: `count` (всего), `off`, `items` — срез. Веб-интерфейс: список грузится по 100 записей, внизу «... ещё N» подгружает следующую страницу.
- **Счётчик DST**: повреждённые DST-фреймы считаются (`s_dst_err_frames`), лог — первая ошибка и далее каждые 16-ю.
- **Подсказка DSD mode** в веб-интерфейсе: под кнопками DoP/Native пояснение про проводку DATA2/DATA_CLK и «применяется со следующего DSD-трека».
- Отложено (нужны актуальные файлы): зеркало громкости с телефона на слайдер UI (требуется текущий ui.c — в базовом main.zip он старый, без play_pause/next_track); кэш плейлиста папки (нет playlist.c). Объявление decoder_request — extern в main.c, перенесите в decoder.h при следующей правке.
