# Пользовательские FIR-фильтры ES9039Q2M: интеграция и диагностика

## Что это

В ES9039Q2M, кроме 8 штатных пресетов (Reg 88 `FILTER_SHAPE`), есть
**программируемый FIR**: 8x-интерполятор собран из двух ступеней —

| ступень | RAM | адреса | роль (рабочая модель) |
|---|---|---|---|
| 2x FIR | 128 коэфф | Reg137: stage=0, addr 0x00–0x7F | главный брикволл: подавляет образ fs |
| 4x FIR | 32 коэфф | Reg137: stage=1, addr 0x00–0x1F | чистовая: подавляет образы 2fs и выше |

Модель подтверждается: полная длина каскада (128/2 → 32/4 полифазных ветвей) даёт
групповую задержку ≈ 33,8 сэмпла входной частоты — ровно столько, сколько
указано в даташите для штатного «linear phase fast roll-off» (33.80/fs).

Загрузка: только SW-режим (I2C). Регистры:

- Reg 135 `PROGRAM RAM CONTROL`: бит 1 `PROG_COEFF_WE` (строб записи),
  бит 0 `PROG_COEFF_EN` (1 = использовать пользовательские коэффициенты,
  0 = встроенный пресет из Reg 88);
- Reg 137 `PROGRAM RAM ADDRESS`: бит 7 — ступень (0 = 2x, 1 = 4x), биты [6:0] — адрес;
- Reg 138–140 `PROGRAM RAM DATA`: 24-битный знаковый коэффициент;
- Reg 246–248 `PROG COEFF OUT READ`: обратное чтение.

Последовательность на один коэффициент (из даташита, стр. 30):

```
Write Reg137 addr        // адрес (и ступень битом 7)
Write Reg138 data[7:0]
Write Reg139 data[15:8]
Write Reg140 data[23:16]
Write Reg135 0x02        // WE=1
Write Reg135 0x00        // WE=0
```

После заливки всех 160 коэффициентов: `Reg135 = 0x01` (EN=1).

**Обратно к встроенному пресету** в любой момент: `Reg135 = 0x00`.

## Файлы

- `main/es9039_fir.h` — API модуля;
- `main/es9039_fir.c` — реализация (полифазная декомпозиция прототипа, запись RAM, readback);
- `main/es9039_fir_coeff.h` / `main/es9039_fir_coeff.c` — сгенерированные коэффициенты:
  C-BRICK и C-SLOW для 44,1 / 48 / 96 кГц;
- `tools/gen_fir_coeffs.py` — генератор (numpy/scipy/matplotlib), перегенерация и новые частоты;
- `fir_brick_response.png`, `fir_slow_response.png` — расчётные АЧХ наборов.

## Интеграция — ВЫПОЛНЕНА в реальный проект (17.11.2026)

Связка модулей — фактическая, по коду проекта:

1. **decoder.c**: первый декодированный кадр → `apply_rate_with_dac(fs)` →
   `es9039_switch_frequency(apply_rate_cb, NULL, 500, fs)`.
2. **Драйвер, `es9039_switch_frequency()`**: mute (Reg 86) → колбэк
   `i2s_out_apply_fs()` (пересборка BCLK/LRCK; MCLK не меняется) → заливка
   FIR-набора под новую частоту через `es9039_fir_apply_for_fs(fs, false)`
   (RAM перезаписывается, пока выход в mute — заливка не слышна) →
   ожидание SRC lock (Reg 239[7]) → unmute.
3. **Драйвер**: `es9039_write_reg()/es9039_read_reg()` — публичные обёртки,
   замещают слабые заглушки es9039_fir.c при линковке.
4. При fs без набора (88,2/176,4/192 кГц и пр.) чип остаётся на встроенном
   пресете (Reg 88 FILTER_SHAPE) — звук продолжается, лог-предупреждение.

Переключение «встроенный ↔ кастомный» на лету: `es9039_fir_use_builtin()` /
повторный вызов `es9039_switch_frequency()` (или прямой `es9039_fir_apply()`).

## Что не документировано ESS и как это диагностировать

App note по программированию FIR ESS отдаёт только дистрибьютору/FAE.
Ниже — четыре неизвестных и процедура их нащупывания на стенде
(REW/Cosmos + тональные сигналы). Каждая проверка — один вечер.

### Неизвестное 1: маппинг полифазных фаз на адреса RAM
`coeff.h` хранит ПРОТОТИП h[0..127] (и h[0..31]); модуль сам раскладывает на
ветви g_p[k] = h[p+k·R]. Две гипотезы адресации:

- `FIR_PHASE_BLOCK` (по умолчанию): `addr = phase*M + tap`;
- `FIR_PHASE_INTERLEAVED`: `addr = tap*R + phase`.

**Тест:** загрузить DELTA (`es9039_fir_load_delta()`), снять АЧХ и уровень.
Прозрачный тракт (плоская АЧХ) при обеих гипотезах возможен только если чип
начинает обход фаз с адреса 0 в том же порядке, что мы заливаем. Если АЧХ
«зубчатая»/узкополосная — переключить `s_phase_map` в `es9039_fir.c` и повторить.

### Неизвестное 2: порядок ступеней в тракте
**Тест:** загрузить DELTA только в ступень 2x (в 4x — дельту тоже), затем
заменить ступень 2x на реальный брикволл, оставив 4x дельтой. Если на выходе
АЧХ срезана по 0,55·fs — ступень 2x стоит ближе к входу (модель верна). Если
срез у Найквиста 4fs — порядок обратный: поменять местами роли в генераторе
(для ступени «первой» использовать спеки с fstop = 1,5·fs и наоборот) и
перегенерировать.

### Неизвестное 3: внутренняя нормировка (гейн)
**Тест:** тональный сигнал 1 кГц −3 дБFS на входе; замер уровня выхода при
встроенном пресете и после загрузки набора. Разница в дБ → целочисленный сдвиг
(кратно 6,02 дБ). Внести в `ES9039_FIR_GAIN_SHIFT` (es9039_fir.h) — точнее,
в общую нормировку `quant()` генератора (`gain` = R в Q1.23 сейчас; при
расхождении на −18 дБ чип нормирует по сумме 1,0 — тогда в генераторе
`quant(h, 1)` для обеих ступеней и перегенерация).

### Неизвестное 4: поведение `PROG_COEFF_OUT READ`
**Тест:** после загрузки прочитать все 160 адресов (функция
`es9039_fir_readback`), сравнить с записанным. Если readback возвращает
не то, что записывали (автоинкремент или мусор) — проверки `verify=true`
отключить и ориентироваться только на замер АЧХ.

## Достигнутые характеристики (симуляция с целочисленными коэфф)

| набор | рябь 0–20к | образ fs | образы 2fs+ | примечание |
|---|---|---|---|---|
| C-BRICK 44.1k | 0,010 дБ | −71 дБ (с 24,3k) | −64 дБ | реплика fs −97 дБ в глубине стопа |
| C-BRICK 48k | 0,008 дБ | −85 дБ (с 26,4k) | −66 дБ | |
| C-BRICK 96k | 0,076 дБ | −46 дБ (с 24k) | −83 дБ | «прибить после 24k», как у автора |
| C-SLOW 44.1k | 0,015 дБ | −55 дБ (с 31,8k) | −62 дБ | импульс 40+32 эфф. тапов |
| C-SLOW 48k | 0,011 дБ | −61 дБ (с 34,6k) | −65 дБ | |
| C-SLOW 96k | 0,005 дБ | −87 дБ (с 69,1k) | −77 дБ | |

Ограничение RAM 128+32 = 160 коэффициентов: переходные зоны шире, чем у
штатного fast (−115 дБ), и глубина подавления образа 2fs ограничена 32 тапами
ступени 4x. Авторские цифры на SPRO (60 дБ выше 24 кГц для 96 кГц) примерно
совпадают с нашими для 96k — RAM Q2M, судя по всему, короче.

   фильтра (linear phase — симметричный звон).
