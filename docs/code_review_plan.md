# Ревью всех патчей проекта и план работ по приоритету
Версия: 20.11.2026 (обновления: 23.11.2026 — 3.10-p4d, блок G; 24.11.2026 — P5-7 закрыт, блок H). Охват: web_remote, ota_upd, usb_host_flash, phono_adc (v4, P4-мастер), dsd_native + DST. Проверено статическим разбором (парность, API-согласованность) и числовыми симуляциями (DSP — float32/numba); компиляция и железо — не проверены (см. п. E).

## A. Критично — исправить до прошивки (P1)

1. **`main/dsd_dec.c` — pad-байт после FRTE не пропущен** (DST-контейнер).
   `parse_dst_container()` делает `if (pos & 1) pos++;` только в счётчике, но не `fseek`. Данные FRTE = 6 байт (нечётные) → после FRTE в файле лежит pad-байт, и первый DSTF будет прочитан со сдвигом на 1 байт → «DST: DSTF-фреймов не найдено» или мусор.
   **Fix:** после строки `if (pos & 1) pos++;` добавить `fseek(ctx->f, 1, SEEK_CUR);`.

2. **`main/dsd_native.c` — конфликт пинов со штатным i2s_out.**
   Порт A dout = GPIO48 и WS_DUMMY = GPIO47 — это те же физические пины, которыми штатный PCM-тракт (i2s_out) продолжает управлять после включения native. Два DMA-источника на один GPIO — мусор в DATA1/WS.
   **Fix:** в `dsd_native_start()` перед `i2s_channel_enable` ставить `i2s_out_set_paused(true)` (синтетическая пауза штатного порта), в `dsd_native_stop()` — снимать. Либо завести хук-колбэк из decoder.c.

3. **`main/decoder.c` — позиция не растёт в native-режиме.**
   В native-ветке цикла `s_dec.samples` не инкрементируется → в UI/web `/api/status` `pos_ms` не движется.
   **Fix:** после успешного `dsd_native_write(...)` добавить `s_dec.samples += n / 2;` (n — байтов интерлива, 2 байта на стерео-кадр).

4. **`main/dst_dec.c` — сверить get_ur_golomb_jpegls.**
   Формула реализована как `(i << k) + val − (1 << k) + 1`. Для k=0 совпадает с unary-кодом, для k>0 расходится с «стандартной» Rice-формулой `i·2^k + val` на −2^k+1. Если формула не совпадает с ISO/IEC 14496-3 subpart 10 — декодер будет портить все фреймы с предсказаниями.
   **Fix:** открыть ISO-спеку/ffmpeg-исходник и сверить формулу бит-в-бит; лучший честный тест — один реальный SACD-DFF-файл на бенче (нет в среде подготовки). До сверки считать DST-декодер «не готов к прослушиванию».

5. **`main/dst_dec.c` — EOF в арифметическом декодере.**
   В `ac_get()` используется хак `(uint32_t)gb_get_bits(...) == 0xFFFFFFFFu && n > 0 → 0`. Работает, но хрупко.
   **Fix:** заменить на явную проверку `int nb = gb_get_bits(...); if (nb < 0) nb = 0;`.

6. **OTA — откат не включён.**
   `ota_upd.c` пишёт образ, но при неудачном стартe новой прошивки плеер встанет без автопоправки.
   **Fix:** `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y` в sdkconfig.defaults + в `app_main()` после успешного старта (например, после первого удачного декодера/web-старта) вызвать `esp_ota_mark_app_valid_cancel_rollback()`. Заодно пометить «первый запуск» флагом в NVS для диагностики.

7. **`main/dsd_dec.c` — pad-байты в общем парсере DFF.**
   Основной цикл `parse_dff()` пропускает чанки через `fseek(sz)` без pad после нечётного ckDataSize (правило IFF: pad-байт после нечётного размера). Один нечётный чанк в PROP (COMT/ABSS и пр.) — и парсер поедет по мусору. В DST-ветке pad учтён, в основном цикле — нет.
   **Fix:** единый хелпер `skip_chunk(ctx)` с учётом pad, использовать во всех ветках.

## B. Важные — надёжность и UX (P2)

8. **Пауза в native-DSD.** При `decoder_pause()` в native-ветке порты продолжают гонять DMA (недозаполненные слоты → мусор). Нужен обработчик паузы: mute ES9039 и/или `i2s_channel_disable` портов с повторным включением на продолжении.
9. **Единый namespace NVS.** `web_ctrl.c` пишет `dsd_mode` напрямую (`nvs_open("dac", ...)`), а `main.c` читает через `persist_load_u8`. Если persist использует другой namespace — значение «потеряется». **Fix:** вести все ключи через один `persist_*` API (проверить namespace) или вынести хук в ui_hooks.
10. **Мьютекс ui_hooks.** Хуки вызываются из httpd-задачи и UI-задачи без синхронизации — гонки при смене источника/громкости. Минимум:critical section или Mutex на set_source_url.
11. **Смена источника блокирует httpd 1–2 с** (decoder_start внутри httpd-хендлера). **Fix:** очередь команд + worker (тот же паттерн, что usb_flash).
12. **Громкость с телефона не зеркалится на слайдер экрана** (старый TODO) — get_volume_db-хук в tick, чтобы UI показывал актуальное.
13. **Дубли кода DSP-самотеста на устройстве.** `phono_dsp_test.c` — ок, но вызов `phono_run_all_tests()` надо включать флагом (в CMake сейчас включён безусловной компиляцией — вынести под `CONFIG_PHONO_DSP_TEST`).

## C. Полезно — UX/производительность (P3)

14. **Веб-пульт:** подсказка в блоке DSD mode («режим вступит в силу со следующего трека»); блокировка кнопок при активном web-запросе (антидребезг); показ версии прошивки и режима DSD в статусе — уже есть поле `dsd`, добавить человекочитаемую строку.
15. **USB:** большие папки (сотни файлов) — `/api/files` отдаёт весь список; сделать пагинацию (offset/limit) — иначе JSON-ответ на 2–3 МБ.
16. **Плейлист из USB/SD:** `ensure_playlist_for_current()` сканирует папку целиком на каждый next/prev — кэшировать список папки при первом заходе.
17. **`dsd_dec.c` — лог повторов DST-фреймов.** Сейчас warning на каждый сбойный фрейм — при плохом файле будет спам. Счётчик + лог раз в 10 повторов.
18. **DSF «bits=8» (MSB-first)** — редко, трактуется как 1 бит; оставить как есть, но логировать явно (сейчас уже логируется).
19. **`phono_adc.c`:** при паузе decoder задача phono теряет блок с логом — можно вместо этого приостанавливать приём (mute/пауза порта RX) — пометить как улучшение, не баг.

### P5-1. DST-декодер на реальных SACD-DFF — главный резерв покрытия

**Цель.** Закрыть последний непокрытый путь декодера: сжатые DST-фреймы с
предсказателями (fsets/probs). Сейчас верифицированы несжатая ветка (selftest
PASS 3/3) и synth.dff (DSD MATCH 9408/9408) — оба на несжатых DSTF.

**Подготовка.** 3–5 реальных треков с DST-сжатием (не «DST-frames as-is»);
эталонные DSD-дампы ffmpeg 9.1 (основной эталон) и 8.0 (перекрёстная сверка —
на 8.0/9.1 DSD-выход уже побайтно идентичен, см. отчёт §3).

**Прогон.** `./tools/dst_bench track.dff --dsd ref.bin` для каждого файла;
критерий — DSD MATCH N/N побайтно.

**При несовпадении.** Локализовать до фрейма (счётчик mismatch в бенче уже есть,
лог каждые 16-й — P3-17); сверить на месте fsets/probs и голомб-декодирование
(`get_sr_golomb_dst`) с ffmpeg 9.1. Любой фикс возвращает пункту статус P1
до перепрохождения всего цикла.

**Риск.** Синтетика не покрывает ветки сегментации на реальных данных —
несовпадение на первом реальном файле это ожидаемый сценарий, а не регресс.

**Побочный результат.** Статистика реальных файлов (доля сжатых фреймов,
распределение размеров DSTF) — в отчёт §5.

### P5-2. Компиляция под ESP-IDF и прошивка на железе

**Шаги.** Чистая сборка: `idf.py set-target esp32p4 && idf.py reconfigure &&
idf.py build`. `dependencies.lock` не править (esp_tinyusb и пр. — по журналу
3.10). Затем `idf.py build flash monitor`.

**Smoke-контроль на живом плеере.** USB-флешка: browse/play; web-пульт: смена
источника через `decoder_request` (P2-11), громкость зеркалится (P2-12);
native-DSD: старт, позиция в `/api/status` растёт (P1-3), пауза mute (P2-8);
лог: счётчик DST-повторов молчит на чистых файлах (P3-17).

**Критерий.** Сборка наших файлов без новых warnings; трек играет до конца;
DST-ошибок в логе нет.

**Риск.** Конфликты пинов/переферии, не видимые статически (см. P5-4) —
проявятся только здесь.

### P5-3. Native DSD: TX-slave на P4 и фазировка двух портов

Пункт из README 7д.1 (риск помечен). Проверить синхронность DATA0/DATA1 и WS
двух I2S-портов в native-режиме: осциллографом (совпадение фронтов WS относительно
DATA) и на слух (шум-смещение каналов при расфазировке). Критерий: биты каналов
идентичны эталону на обоих портах. При расхождении — планирование отдельного
патча (перевод второго порта на общий BCLK/MCLK).

### P5-4. Сверка пинов по схеме платы

GPIO14–17 (фоно-ADC) и DATA2/DATA_CLK (native DSD) — сверить с фактической
схемой платы: нет конфликтов с i2s_out, дисплеем, Wi-Fi, GT911. Критерий: нет
пересечений назначений; любые расхождения кода и платы — в исправление `Kconfig`/
дефайнов до прошивки (блокирует P5-2 частично).

### P5-5. OTA-откат на железе (процедура из п. F)

`first_boot` (namespace `ota_upd`) отражает событие. Повторить с подтверждением —
флаг сбрасывается, отката нет.

### P5-7. PCM ±1 LSB — ✅ закрыто (24.11.2026)

Факт верификации: 14 позиций из 94 080 (0,015 %), канал L, граница полшага,
FP-режим генератора эталона; на DSD-биты не влияет, на слух не различимо.

**Обоснование закрытия (б) + инструмент из (а).** Механизм найден и
подтверждён вычислением из самих данных проекта:
- путь эталона: double → float32 (fltp) → x*2^15 (умножение на степень
  двойки — точное) → llrint (round-half-even) → clip int16;
- путь порта: double → x*32768 → floor(+0.5) (round-half-up) → clip;
- float32-квантование сдвигает значение на ≤ |t|·2^-24 и подтягивает
  величины около k+0.5 к точной границе; на границе llrint округляет к
  чётному, порт — вверх → расхождение ровно 1 LSB;
- в double точных тай не существует (round-half-even в double даёт
  0 расхождений с портом) — значит, эталон шёл именно через float32;
- эмпирика: на богатом случайном сигнале (канал L, 47 040 сэмплов)
  10-26 расхождений на прогон, среднее 17,1 — замер золотого прогона
  (14) внутри диапазона; все расхождения в пределах ~0,001 от границы
  полшага, макс diff ровно 1 LSB; канал R золотого прогона тихий
  (значения не попадают в окно границы) — 0 расхождений, что объясняет
  «все 14 только в L»;
- расхождение локализовано в финальной конверсии s16, а не в декодере:
  DSD-биты (критерий корректности) совпали 94080/94080.

**Инструмент (из варианта (а)).** В `tools/dsd2pcm.py` добавлен режим
`--s16f32` — бит-в-бит путь ffmpeg/swr (float32 + ties-even). При повторной
сверке с эталоном (ffmpeg на доступной машине) сравнение должно стать
побайтовым: `python3 dsd2pcm.py synth_out.bin --s16f32 ref_s16.raw --channels 2`.
Путь порта точнее эталона (double vs float32) — менять его на артефактный
не требуется; `--s16` (double) оставлен основным.

**Замечание.** Список 14 позиций (журнал старой сессии) не сохранился;
его смысл восстановлен механически — это тай-позиции float32-пути
эталона, воспроизводимые при наличии эталонного файла.
